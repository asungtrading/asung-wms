## ① 픽·팩 라인 3색 — 「아직 안 함」과 「덜 채움」이 같은 흰색이었다

요구(Caleb): 수량 기준 세 갈래 — **0개 = 흰색 · 1~요구량 미만 = 주황 · 도달 = 초록.**
색이 주황인 이유: 빨강은 이 프로젝트에서 **오류·차단**(Hold·실패·flash bad)에 쓰이는데,
「덜 채움」은 오류가 아니라 **재고가 없어 못 채운 정상 상태**일 수 있다. 주황은 이미
「주의·확인 필요」(Held 칩·unexpected)라 의미가 맞는다.

**판정은 status 컬럼이 아니라 수량 비교다** — picker/packer 렌더는 status 를 읽지 않는다
(`status` 는 저장용, picker.html:1405 `picked>=assigned?"picked":"short"`). 그래서 이번 수정도
상태 계산·DB·EF 무접촉이고 렌더 4곳(목록 2 + 싱글뷰 2)과 CSS 만 바뀌었다.

📌 **DB 는 이미 세 갈래를 알고 있었다 — 화면만 두 갈래였다.** `saveLine` 이 라인 저장 때
쓰는 status 가 픽·팩 양쪽 모두 **정확히 같은 경계**로 세 갈래다:
```
picker.html:1338   picked >= assigned ? "picked"   : (picked   > 0 ? "in_progress" : "pending")
packer.html:1300   verified>= required ? "verified" : (verified > 0 ? "in_progress" : "pending")
```
`in_progress`(=부분 채움)가 스캔할 때마다 저장되고 있었는데 **화면에는 그 구분이 없었다.**
⇒ 이번 3색은 새 개념을 만든 것이 아니라 **이미 저장하던 상태를 눈에 보이게 한 것**이다
(그래서 상태 계산에 손댈 필요가 없었다).

📌 **픽에는 옛 흔적이 남아 있었다** — 목록 렌더가 `short` 변수를 계산만 하고 **어디에도 쓰지
않았다.** Caleb 이 말한 "구분이 안 된다"의 코드 실체가 이것이다(이번에 제거).

### ⚠️ 팩 「초과」는 새 색이 필요 없었다 — 「네 갈래」 가정이 틀렸다

작업 중 Caleb 이 "팩은 초과도 있으니 네 갈래"로 범위를 넓혔고, 조사가 **그 전제를 정정**했다:

### 📌 부수 발견 — `--warn-bg` 가 **처음부터 미정의**였다 (42일)

`overchip`(packer.html:79)·`overalert`(:75)가 `background:var(--warn-bg)` 를 쓰는데

**배경이 투명**으로 렌더돼 테두리와 글자만 주황이었다.


Caleb 이 "초과 칩이 표시는 되는데 눈에 덜 띈다"고 인지하고 있던 것의 원인이 이거였다.

**이번에 `--warn-bg:#f9e6b8` 로 정의**(픽·팩 두 파일 — 팔레트가 복제 구조라 함께).
값 근거 = **명도 사다리**(이 순서가 깨지면 안 된다):
```
부분 행 배경 #fdf6ec (~96%)  <  초과 칩·배너 배경 #f9e6b8 (~85%)  <  칩 테두리 #f5dcae (~82%)

```
같은 앰버 계열이라 주황의 기존 의미(주의·확인)와 일관하면서, **행은 옅고 칩은 진해
형태(면적)와 명도 둘 다로 갈린다** — 주황을 「부분」과 「초과」 두 곳에 쓰면서도 안 섞이는 이유.

### 클래스 조립을 병기로 — 부분인 현재 라인이 테두리를 잃을 뻔했다

종전 조립은 단일 삼항이라 상태가 **하나만** 붙었다:
```js
const cls = done ? "done" : (idx===curIdx ? "cur" : "");
```
여기에 partial 을 그냥 끼우면 **부분이면서 현재인 라인**이 「지금 스캔할 라인」 표시
(픽=파랑 `--accent:#2f6df6` · 팩=보라 `#7a5af0` 테두리+글로우)를 잃는다. 배경과 테두리는
**직교 레이어**이므로 병기로 바꿨다(`done` 은 종전대로 단독 — 완료 행 무테두리 관행 유지).

⚠️ **세션 성격**(0건을 읽을 때의 주의 — "얕게 지나간 세션의 0건은 안 봤다일 수 있다"):
