## 1. 방향이 바뀌었다 — 화면은 검증의 보상이 아니다

오전까지 나(원장 세션)는 이렇게 잡고 있었다.

> 「검증이 깨끗해지면 화면을 연다 — 원인 미상이 많은 화면은 한 번 보고 안 본다」

**Caleb 이 뒤집었다:**

> 그 조건에는 끝이 없다. 오늘도 새 문제가 셋 나왔다.
> 그리고 **나는 화면을 못 보니 네 코드에만 의존한다** — 뭘 놓쳤는지 알 수도 없다.
> 차라리 WMS 처럼 **다 만들고 고쳐나가는** 것이 맞지 않나.

⚠️ **맞다.** 그리고 더 결정적인 것은 **오늘 찾은 셋 중 둘이 사람이 이미 아는 일**이었다는 점이다.

| 어긋남 | 실제 원인 | 아는 사람 | 우리가 쓴 시간 |
|---|---|---|---|
| `SKL01861` | `TR-04169` 로 자리를 옮겼다 | 창고 | 약 2시간 역추적 |
| `UNF18050~53` | 조립 `FG-00131` 이 취소됐다 | 조립 담당 | 재고 −6 에서 파냄 |

⇒ **화면은 검증 도구다.** 창고 사람은 **소비자가 아니라 정보원**이다.

### ⚠️ 다만 WMS 와 다른 점 하나 — 처방까지

```
WMS       화면이 틀리면 사람이 안다 — 물건을 보고 있으니까
원장 재고  8,060 SKU 를 다 볼 수 없다 — 틀려도 모를 수 있다
```

📌 **처방: Cin7 열을 나란히 둔다.** 「원장이 정답」이라 주장하지 않는다.
⇒ 틀린 숫자가 **위험이 아니라 보이는 것**이 된다. 그리고 아무 SKU 나 찍어볼 수 있으니,
「이상만 보여주는 화면」보다 **오히려 안전하다.**

## 3. ⚠️⚠️ 시점 컷오프 — 세 번 고쳤다

### 문제

```
[실측 · 같은 날 · 같은 정의]
  아침 08시   토론토   9칸 · 격차   52
  오후 14시   토론토 475칸
```

Cin7 스냅샷은 **01:21 의 한순간**인데 원장 델타는 **그 뒤로 계속 쌓인다.**

⚠️ 그리고 **실제 피해도 났다** — `inv_snap_balance_diffs()` 를 오후에 수동으로 돌려
**475행이 굳었다**(삭제함). 아침이면 9행이었다.

### ❌ 1차 실패 — 날짜 필터

`occurred_on < 오늘` 로 잘라봤더니 **오후 49칸**. 더 나빠졌다.
⚠️ **01:21 스냅샷은 그날 00:00~01:21 사건을 이미 포함**하는데 날짜로 자르면 그것까지 뺀다.
⇒ 나는 여기서 **「순간은 못 맞춘다」고 결론지었다.** 틀렸다 — **`created_at` 을 못 봤다.**
📌 WMS 세션이 짚어줬다.

### ① `created_at` 컷오프 — 475 → 161

```sql
where l.created_at <= 스냅샷의 taken_at
```

⚠️ **아직 9칸이 아니다.**

### ② `manual` 면제 — 161 → 7

**우리 정정까지 잘렸다.** 정정은 **사건 시각이 과거인데 기록 시각은 현재**다.

```
[실물 ANN01111] 라이브 20(Cin7 과 일치 ✅) · at_snapshot −4 · diff −24
⇒ 컷오프가 상쇄를 잘라 **상쇄 전 상태로 되돌렸다**
total 157 = 그날 아침 상쇄한 경계 오더 행 수와 정확히 같다
```

```sql
where l.source = 'manual' or l.created_at <= la.at
```

📌 `manual` 은 **「스냅샷 시점에 원장이 알았어야 할 사실」**을 뒤늦게 적는 것이다.
⭐ 그리고 그것이 원하는 동작이다 — **고쳤으면 대조가 바로 맞아야** 한다.
⚠️ **대가**: `manual` 을 잘못 넣으면 대조가 **즉시** 그것을 정답으로 받아들인다.
정정 전에 근거를 `raw` 에 남기는 관례가 그래서 중요하다.

⚠️ **아직 7칸이다.**

### ③ ⭐ 축이 틀렸다 — 7 → 2 (+ 새 5개)

```
[실물 WTA00219 A070401 · 원장 402 · Cin7 342 · diff +60]
  manual :binfixed             −60   포함(면제)
  manual :binfixed:superseded  +60   포함(면제)   → 합 0
  cin7   A070401               −60   ⚠️ 오늘 낮 수집 → 잘렸다
⇒ 상쇄와 재기록이 짝인데 **반쪽만** 들어왔다
```

⭐ **자르고 싶은 것은 「스냅샷 이후에 *일어난* 사건」인데 「스냅샷 이후에 *수집된* 행」을
잘랐다.** `cin7 A070401` 은 `occurred_on` 8/21 이고 **Cin7 스냅샷이 이미 반영한 사건**이다.

```sql
where l.source = 'manual'
   or l.occurred_on < (la.at at time zone 'America/Toronto')::date   -- ⭐ 과거 사건은 무조건
   or l.created_at <= la.at
```

| 경우 | 결과 |
|---|---|
| 과거 사건(8/21)을 오늘 늦게 수집 | ⭐ 포함 — Cin7 이 이미 반영했다 |
| 오늘 사건을 오늘 수집 | 잘림 |
| 오늘 사건인데 01:21 이전 수집 | 포함 — `created_at` 이 가른다 |
| `manual` 정정 | 포함 |

⚠️ **날짜 필터 단독으로는 안 된다**(1차 실패). **`created_at` 과 함께 써야** 순간이 맞는다.
⚠️ 이 부류는 계속 생긴다 — **커서가 밀리거나(결함 C·D) 재수집하거나 bin 규칙을 바꾸면**
과거 사건이 오늘 수집된다.

📌 **차분 검증**: 같은 시드를 구판 술어로 돌리면 `TESTA +60`(`WTA00219` 실물 모양)이
나오고 새 뷰는 0이다.

### ✅ 결과

```
WTA00219/220/286 · SBO70659 · SKL01861 이 전부 사라졌다
UNF18050~53 · UNF18261 은 FG-00131 상쇄로 해소
남은 것: BNAT48173 +11 · CAN01003 −4 · PRO00124 짝 · ⚠️ 새 5개(각 −1)
```

**측정 자체가 함정일 수 있다.** 같은 날 같은 쿼리가 **9 · 49 · 128 · 475 · 161 · 7 · 9** 를 냈다.
⇒ **언제 재느냐, 무엇으로 자르느냐가 무엇을 재느냐만큼 중요하다.**

## 4. 「확인됨」 축 — WMS 조건 ②

> 영구 비영 항목이 있는 채로 카드를 띄우면 **매일 빨간불**이 되고, 「7 이 8 이 되는 날」을
> 놓친다. 무시되는 경고는 **없는 것과 같다.**

⚠️ **「확인됨」과 「해결됨」은 다르다.**

| | 누가 | 뜻 |
|---|---|---|
| **확인됨** | ⭐ 창고·매니저 | 원인을 안다. 숫자는 아직 틀려 있다 |
| **해결됨** | 원장 | 상쇄를 넣어 실제로 맞췄다 |

📌 **「해결됨」 버튼을 만들지 않았다** — 상쇄를 넣으면 **다음 회차에 목록에서 저절로 사라진다.**

⭐ **승계**: `checked_on` 마다 행이 새로 생기므로 **직전 회차에서 물려받는다**
(`first_seen_on` 과 같은 규칙). ⚠️ **해소됐다 재발하면 확인을 새로 받는다.**

⚠️ **알려진 의미론**(Claude Code 지적): 승계 차단은 「직전 회차 일지에 그 칸이 없음」으로
판정한다. **어긋남이 0이라 회차 자체가 비는 날은 건너뛰고** 그 전 회차에서 승계한다.
📌 지금은 그런 날이 없어 실현되지 않았다. **원장이 깨끗해질수록 그 날이 온다** — 그때 다시 볼 것.

**실물**

```
unack 9 → 8   ⭐ 확인 누르니 카드 숫자가 갈렸다
total 9 · new_today 9 · abs_gap 26
```

## 5. ⭐ Claude Code 가 잡은 내 오류 넷

이 세션에서 지시서 자체가 틀린 것을 네 번 잡혔다. **전부 내 의도와 SQL 이 어긋난 곳**이었다.

| | |
|---|---|
| `anon` 회수 누락 | 뷰가 소유자 권한으로 돌아 `inv_ledger` 회수를 **우회**한다 |
| `IN_TRANSIT` 의 `diff` | `coalesce(cin7,0)` 이면 **IN_TRANSIT 전 칸이 「이상」**이 된다 |
| ⭐ Cin7 에만 있는 칸 | `left join` 이면 빠진다 — **`SKL01861` 의 거울칸이 그 부류**였다. 실사고의 절반이 「이상만 보기」에서 안 보였을 것 |
| `first_seen_on` 승계 | `min(전체 과거)` 는 **「재발하면 새 시작」이라는 내 규칙을 스스로 위반** |

📌 그리고 **`ledger_qty_at_snapshot` 열**은 Caleb 이 요구했다 — 없으면 화면에서
「5 랑 7 이 다른데 왜 diff 가 0 이지」가 된다.
