## ⚠️ 보류 — 개인 평가 목적 (Caleb · 나중에 다시 논의하지 않기 위해 남긴다)

   방법이 「스캔 건너뛰기」**다. 측정하려던 바로 그 품질이 측정 때문에 무너진다.
⇒ 화면은 **문서·단계 단위**로만 읽히게 둔다(순위·강조·색 차등 금지 관례와 같은 계열).

## ⬜ 다음 — 리시빙 단계별 시간 화면 (기록은 시작됐고 화면은 데이터가 며칠 쌓인 뒤)

판단할 것:
- 스캔 구간 / 풋어웨이 구간 표시 — ⚠️ **겹칠 수 있으므로 합산 금지, 병기**
  (정의: 스캔 = `created_at ~ max(last_qty_at)` · 풋어웨이 = `min(stage='putaway' at) ~ completed_at`
   — 끝에 Place all 만 누르는 관행에도 견디는 유일한 형태. **걷는 시간이 이 정의로만 들어온다**)
- **Hold·partial 공제를 어느 단계에서 뺄지** — 지금 공제는 문서 전체 구간 기준이다
- 오늘 만든 `Workers (last touch)` 열을 **축 기반으로 갈아탈지** — 그러면 **각주도 다시 써야 한다**
  ("스캔 축은 Place all 이 못 덮는다"로 완화 가능)
- **복귀 빈도**(`stage='receiving'` 행 수) 실측 → 막을지 판단

```sql
-- ① 축·전환이 실제로 쌓이는가 (며칠 뒤 첫 확인)
select count(*) filter (where last_qty_at is not null)     as qty_axis,
       count(*) filter (where last_putaway_at is not null) as putaway_axis,
       count(*) as lines
  from wms_receipt_lines where last_received_at >= '2026-08-26';

-- ② 문서별 단계 구간 + 사람 수 (화면의 원형 — 겹침이 보인다: scan_end > putaway_start 면 교차)
select r.id, r.po_number, r.created_at, r.completed_at,
       max(l.last_qty_at)                        as scan_end,
       count(distinct l.last_qty_by)             as scan_people,
       count(distinct l.last_putaway_by)         as putaway_people,
       (select min(e.at) from wms_receipt_stage_events e
         where e.receipt_id = r.id and e.stage = 'putaway') as putaway_start
  from wms_receipts r join wms_receipt_lines l on l.receipt_id = r.id
 where r.created_at >= '2026-08-26'
 group by r.id, r.po_number, r.created_at, r.completed_at
 order by r.created_at desc;

-- ③ 복귀 빈도 (막을지 판단의 유일한 근거 — 추측 금지)
select receipt_id, count(*) filter (where stage = 'putaway')   as to_putaway,
                   count(*) filter (where stage = 'receiving') as back_to_receiving
  from wms_receipt_stage_events group by receipt_id order by 3 desc;
```

## 그 밖

- **partial 은 현재 0건** — 기능은 실재하나(RPC·게이트 확인 완료) 쌓인 데이터가 없다.
  단계별 공제 설계는 실물 partial 이 한 건 나온 뒤에 판단하는 것이 안전하다.
- **스캔 횟수 기록(미해결 2)은 이 축 테이블로도 안 풀린다** — 축도 「마지막 터치」 한 칸이라
  라인당 몇 번 찍었는지는 안 남는다. **이벤트 로그(append-only) 별건**이고, 조사에서 최소 필드·
  기록 지점·규모(2~3일)까지 설계해 뒀다(같은 조사를 반복하지 말 것).
