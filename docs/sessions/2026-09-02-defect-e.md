## 2. ⭐⭐ 결함 E — 커서 아래 문서의 편집을 못 본다

에드먼튼 15칸이 한 사건이었다.

```
UNF18046~18057   12 SKU 각 −12   원장 0 · Cin7 12   ← 재료
UNF18259/260/261 각 +2           원장 2 · Cin7 0    ← 완제품
```

### 추적 — 세 가설이 차례로 깨졌다

| 가설 | 결과 |
|---|---|
| 조립 취소(어제 발견한 구멍) | ❌ 원장의 조립 넷은 **전부 토론토**. 에드먼튼 최근 건은 8/20 로 기초 스냅샷 이전이다 |
| Disassembly(안 보는 축) | ❌ `disassemblyList` **Total 0** |
| 새 조정(`ST-01290`+) | ❌ 최신이 `ST-01289` 다 |

⭐ **Cin7 화면의 이동 내역이 답을 줬다** — `UNF18046` 에드먼튼 `ED010702` **`+12`** 를
넣은 것이 **`ST-01283`**(8/31)이었다.

### 실사고

```
8/31 13:11   수집. 그때 내용 = 완제품 UNF18259/260/261 각 +2 (에드먼튼 EU050402)
9/1          실무가 정정 — 「완제품이 아니라 재료였다」
             ST-01283 을 **편집**해 재료 12 SKU 각 +12 (ED010702) 로 바꾸고
             토론토에서 ST-01286 으로 같은 재료를 뺐다
             ref = "Shrikage - UNI (EDM Transfer Adjustment For ST-01283)"
9/2 아침     ⚠️ 원장은 여전히 옛 3행을 들고 있었다
```

**[실측] Cin7 의 지금 `ST-01283`**: `ExistingStockLines` 0건 · `NewStockLines` **12건**.
**원장**: 3행. ⇒ **완전히 다른 내용이었다.**

### ⚠️ 왜 못 봤나

`adjustment` 는 **②-a 축(문서번호 커서)** 이고 커서가 `ST-01289` 로 전진했다.
⇒ `ST-01283` 은 **커서 아래**라 `skip_before_floor` 로 떨어지고 **다시 읽지 않는다.**

📌 **어제 문서에 이미 적어둔 한계다** — 「롤링 재확인은 `transfer` 만 완전 커버리지 ·
`adjustment`·`assembly` 는 커서가 전진해 후보에서 빠지므로 닿지 않는다」.
⇒ **하루 만에 실현됐다.**

⭐ **그리고 bin 단위 대조가 잡았다.** 창고 단위로는 안 보였다(⇒ ② unknown 에도 이 부류가
들어 있었지만 SKU 목록만으로는 원인을 알 수 없었다). **어제 만들지 않았으면 몰랐다.**

### 처방 (커밋 `d087fd2` · `inv-collect@2026-09-02.1`)

```
②-a 에서 목록 행의 사건 날짜가 **최근 7일** 안이면 커서 아래라도 후보에 남긴다
```

- 소스별 날짜: `adjustment`=`EffectiveDate` · `transfer`=`Departure`/`Completion` 중 늦은 것 ·
  `assembly`=`Date`→`Completion`→`WIP` 폴백
  ⚠️ **목록에서 얻는다** — 상세를 부르기 전에 판정해야 한다
- ⚠️ 비용은 `inv_doc_state` 가 지운다(안 바뀐 문서는 상세 미조회)
- ⭐ **창 문서는 커서에 관여하지 않는다**(Claude Code 판단). 지시서는 「전진에 포함」이었으나
  **전진값으로 쓰면 커서가 후퇴**하고 **hold 로 세우면 위쪽 전진을 막는다.**
- ⭐ `dispositions` 맵에 새 키를 만들지 않았다 — 그 맵은 회차 로그가 `hold_capped` 를 뽑는
  자리라 오염되면 로그가 어긋난다
- ②-b 무접촉 — 거긴 `UpdatedSince` 라 편집되면 목록에 다시 나온다. **구조가 다르다**

**✅ 실물**: `recheck_window 34` · `detail_fetched 33` · `no_date null`
⇒ 다음 회차에 **재료 12행이 자동으로 들어왔다.**

## 3. ⚠️⚠️ 소멸 감지의 사각지대 — 축 둘

새 12행은 들어왔는데 **옛 3행이 안 지워졌다.**

```
[실측] missing_lines_skipped_no_lmo 33 = detail_fetched 33
⇒ 조회한 문서 **전부**가 A 집합에서 빠졌다
```

**원인**: 소멸 감지는 「언제 편집됐나」를 알아야 판정하는데 **그 값이 목록에 없다.**

| 축 | `LastModifiedOn` | 소멸 감지 |
|---|---|---|
| `transfer` | ✅ 있다 | 작동 |
| **`adjustment`** | ❌ 없다 | ⚠️ **사각지대** |
| **`assembly`** | ❌ 없다 | ⚠️ **사각지대** |

```
stockAdjustmentList  TaskID · EffectiveDate · StocktakeNumber · Status · Account ·
                     Reference · Comment
finishedGoodsList    TaskID · AssemblyNumber · … · Date · Status · Notes · CustomField1~10
stockTransferList    … · LastModifiedOn   ⭐ 이 축만 있다
```

⇒ **그 둘의 라인 삭제·교체는 아무도 못 본다.** `bin` 대조만이 잡는다.

📌 부수 효과: 그 둘은 `inv_doc_state` 도 같은 값을 쓰므로 **매 회차 상세를 다 부른다**
(오늘 `skipped_unchanged 0`). ⚠️ 비용은 크지만 **덕분에 재조회 창이 잘 작동한다.**

### ⬜ 처방 후보 (미착수)

`LastModifiedOn` 은 **판정 기준**이지 A 집합의 재료가 아니다. 그리고 그 둘은 **매 회차 전량
상세를 부르므로 재료가 이미 있다.**
⇒ **`lmoRaw` 조건만 완화**하면 될 가능성이 크다.
⚠️ 안전장치는 이미 있다 — `listAborted`·`truncated`·`detailCapped` 면 판정 자체를 건너뛴다.

## 5. ⭐ 남은 6칸 — 스냅샷을 소급해 발생 시점을 다 찾았다

`first_seen_on` 은 9/1부터지만 **스냅샷이 8/20부터 매일 있다.** 그것으로 열하루를 되짚었다.

**방법**: 각 날짜 스냅샷마다 「그 시점 원장 잔고(기초 + 컷오프 델타)」와 「그날 Cin7」을 대서
**`diff` 가 0에서 값으로 바뀌는 날**을 찾는다.

| 칸 | 갈라진 날 | 성격 |
|---|---|---|
| `WEL04770` · `WEL04771` (`A090203`) | **9/2** | ⚠️ 미규명 |
| `BNAT48173` +11 · `CAN01003` −4 | **8/29** | 결함 C(커서 동결)가 터진 날 — 혼란기의 잔재 |
| `PRO00124` 짝 (에드먼튼) | 8/20~8/24 | 에드먼튼 내부 bin 이동 · 초기 수집기 시절 |

### ⚠️ `WEL04770`·`WEL04771` — 오늘 처음 생겼고 원인을 못 찾았다

```
8/20 ~ 9/1   줄곧 0
9/2          ⭐ 둘 다 처음 1
```

⇒ 9/1 01:21 ~ 9/2 01:21 사이에 **Cin7 이 1씩 뺐다.** 같은 bin · 같은 크기 = **한 사건**이다.

**소거한 것들**

```
크레딧 노트     원장·Cin7 양쪽에 없다
다른 bin        A090203 말고는 전부 0 (에드먼튼 ED020703 4개는 원장도 안다)
allocated       ⚠️ 스냅샷은 OnHand 를 쓴다(코드 확인). Available 은 대상이 아니다
조립·조정       해당 없음
기준선 경계     ❌ 8/20~9/1 이 0 이었으므로 아니다
Cin7 Movements  ⚠️ WEL04770 은 최신이 8/27 인데 재고가 줄었다 — **이동 기록이 없다**
그 bin 의 다른 SKU  BIG03006 +36(PO-01216)뿐이고 원장이 정상 수신했다
```

📌 「기초 경계 잔재」로 보려 했으나 **소급 조회가 그 가설을 깼다.**
⇒ **⭐ 스냅샷 소급이 가설을 검증하는 도구가 된다.** 앞으로 미상 어긋남에는 이것부터 돌린다.

### 처리 — 「확인됨」으로 표시

여섯 다 `inv_ack_diff` 로 표시했다(`unack` 15, 나머지는 그날 해결한 15칸의 일지 기록).
⚠️ **상쇄하지 않았다** — 원인을 모르는 채 상쇄하면 **원장을 Cin7 에 맞추는 것**이고,
그러면 대조가 아무것도 못 잡게 된다. 「모르면 비워둔다」의 연장이다.

📌 **내일 값이 판정한다**: 그대로 1 → 고정된 어긋남 · 0 → 지연이었다 · 2 → ⚠️ 계속 새는 중.

## 7. 📌 오늘의 교훈

**어제 만든 것이 오늘 값을 했다.**

```
bin 단위 대조   결함 E 를 잡았다 — 창고 단위로는 안 보였다
재조회 창       배포 당일에 재료 12행을 자동으로 회수했다
jobid 18 승계   확인 표시가 하루를 넘어 살아남았다
```

⚠️ 그리고 **어제 적어둔 한계가 하루 만에 실현됐다.** 「닿지 않는다」고 쓴 것을 그대로 겪었다.
⇒ **알려진 한계를 적어두는 것이 다음 날의 진단서가 된다.**

📌 그리고 **스냅샷 소급이 새 도구가 됐다.** 「기초 경계 잔재」라는 그럴듯한 가설을 세웠는데,
열하루를 되짚으니 **8/20~9/1 이 줄곧 0** 이었다. ⇒ 가설이 깨졌고 **오늘 생긴 것**임이 드러났다.
⚠️ 원인을 못 찾은 것은 여전하지만, **「언제 생겼나」를 아는 것만으로도 후보가 크게 줄었다.**
